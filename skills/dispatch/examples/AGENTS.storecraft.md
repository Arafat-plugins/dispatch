# AGENTS.md — repo map for sub-agents

Read this before touching anything. It replaces surveying the codebase.
Human-facing context lives in `CLAUDE.md`; this file is the working map.

## What this project is

StoreCraft — an all-in-one commerce plugin for WordPress. Requires WP 6.4+ and PHP 8.1+.
Text domain `storecraft`. Default PR branch is **`wp-saasing`**, not `main`.

It ships in three editions: Lite, Pro (separate `storecraft-pro` plugin, sibling directory) and
Hub (Cloud/licensing, third repo `storecraft-hub`). Themes consume its shortcodes and hooks as a
public contract.

## Layout — what lives where

| Path | Holds | Edit when |
| --- | --- | --- |
| `includes/` | Legacy procedural `SC_*` classes, snake_case, no namespace | Changing behaviour that already lives here |
| `src/` | New code, `StoreCraft\` namespace, PSR-4 | New non-trivial subsystems |
| `assets/css`, `assets/js` | Frontend + admin assets (27 CSS, 23 JS) | Styling and browser behaviour |
| `blocks/src` | Gutenberg block sources (30 blocks) | Block editor work |
| `blocks/build` | **Committed build output** — generated by `npm run blocks:build` | Never by hand; rebuild and commit |
| `templates/` | Frontend PHP templates | Markup changes |
| `tests/` | `Unit`, `Integration`, `Smoke` (168 files), `Browser`, `k6` | Always, alongside a change |
| `tools/`, `packaging/` | Packaging + smoke runners | Release plumbing |
| `docs/` | Internal docs — never shipped | Design records |
| `vendor/`, `node_modules/` | Dependencies | Never |

**The `includes/` vs `src/` split is the thing to get right.** PHPCS lints `src/` **only**
(`phpcs.xml.dist`). `includes/` is grandfathered out. Follow the file you are already in — do
not half-migrate a legacy class into the namespace as a side effect of an unrelated fix.

## Where things are

- **Bootstrap / entry point:** `storecraft-base.php` — singleton `StoreCraft_Plugin::get_instance()`,
  with `load_core()` → `init_components()` → `register_hooks()`. No service container. It also
  registers a PSR-4 fallback autoloader for `StoreCraft\` → `src/`, so new namespaced code works
  without `composer dump-autoload`.
- **REST routes:** `includes/class-rest-api/class-rest-*.php`, one file per resource
  (`products`, `cart`, `orders`, `customer`, `reviews`, `pricing`, `locations`, `mobile`,
  `product-types`). **These files are the source of truth for the route list**; `README.md`
  documents the public surface.
- **Shortcodes:** `includes/class-shortcode/` — storefront output is shortcode-driven, not
  blocks-only. `[storecraft_products]`, `[storecraft_cart]`, `[storecraft_checkout]`, …
- **Single product sections:** `includes/single-product/sections/`
- **Feature gate:** `includes/class-features.php` (`SC_Features`, option `sc_feature_flags`)
- **Schema:** `includes/class-database.php` — StoreCraft owns its own `wp_sc_*` /
  `wp_storecraft_*` tables rather than reusing WP core tables. Full list in `README.md`.
- **Theme contract:** `docs/THEME-CONTRACT.md` — the stable shortcode/hook surface.
- **Edition boundary:** `docs/STORECRAFT-MODULAR-COMMERCE-BOUNDARY.md`

`src/` is organised by commerce domain, not by layer: `Catalog`, `Checkout`, `Payments`,
`Pricing`, `Tax`, `Shipping`, `Couriers`, `Fulfillment`, `Inventory`, `Customer`, `Locations`,
`Reviews`, `Email`, `Webhooks`, `Queue`, `Audit`, `Logging`, `Observability`, `Privacy`, `Money`,
`Http`.

## Conventions that will get a change rejected

- `if (!defined('ABSPATH')) { exit; }` at the top of **every** PHP file.
- 4-space indent. No closing `?>` in class files.
- Escape on output — `esc_html_e`, `esc_attr` — always with the `storecraft` text domain.
- Comments explain **why**, in prose, at the density of the surrounding file. This codebase does
  not comment obvious lines.
- Assets are versioned by `filemtime()`, not `SC_VERSION` (`SC_Blocks::asset_version()`,
  `includes/bootstrap/class-assets.php::get_asset_version()`). **Editing a CSS file is enough to
  bust the cache — never bump a version for that.**
- A Gutenberg block is a chain: `block.json` attributes → `edit.js` `InspectorControls` →
  `render.php` → the matching shortcode. Change one, check all four.

## Do NOT

- **do NOT** edit `blocks/build/` by hand — it is committed on purpose so a plain `git pull`
  gives a working plugin with no npm step. Edit `blocks/src`, run `npm run blocks:build`, commit
  both.
- **do NOT** edit `vendor/` or `node_modules/`.
- **do NOT** break the edition boundary. Cart, checkout, archive, single product, account,
  order-received, public REST reads and frontend assets **must work with Pro absent and Cloud
  disconnected**. Pro presence is `class_exists('StoreCraft_Pro')`. Lite-only UI advertising Pro
  must render as an **inert, disabled** affordance — never load Pro code paths from core.
- **do NOT** load an optional module without its gate. Guard with `SC_Features::is_enabled('cart')`
  and friends, the way `includes/single-product/sections/action-buttons.php` does.
- **do NOT** change shortcode names, hook names, or documented CSS class names — `docs/THEME-CONTRACT.md`
  is a contract with themes.

## Which agent does what

Routing prefers the repo's own agents — they carry StoreCraft's conventions.

| Role | Agent | Model |
| --- | --- | --- |
| PHP/JS features and fixes | `storecraft-dev` | inherits |
| CSS, responsive, browser-verified | `storecraft-design` | inherits |
| Pre-commit audit (read-only) | `storecraft-commit-check` | inherits |
| Read-only DB inspection | `dispatch-db-tester` | sonnet |
| Security critic (never edits) | `dispatch-security-critic` | haiku |

For a change going to commit, run `storecraft-commit-check` first, then the security critic on
top — the first knows this codebase's rules, the second knows what to be suspicious of.

(`~/Local Sites/flamebubbles/app/public`). DB `local`, user `root`, prefix `wp_`.

Local's bundled binaries fail on missing shared libs unless pointed at Local's own lib dir:

```bash
export LD_LIBRARY_PATH=/home/arafat/.config/Local/lightning-services/mysql-8.0.35+4/bin/linux/lib
```

The MySQL socket path rotates — re-check it before assuming a connection string works. The DB is
often down; that is expected, not a bug to chase.

## What not to bother reading

- `vendor/`, `node_modules/` — dependencies.
- `blocks/build/` — generated. Read `blocks/src/` instead.
- `dist/` — packaging output.
- `docs/` — design records and plans, not current-state truth. Read a specific one only when
  the brief names it. `THEME-CONTRACT.md` and `STORECRAFT-MODULAR-COMMERCE-BOUNDARY.md` are the
  two that constrain code.
- `tests/Smoke/` in bulk — 168 files. Read only the one that covers your surface.
- `storecraft-pro.pre-split-backup-*/` (sibling) — a dead backup.
